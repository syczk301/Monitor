# 4.8.2：预览帧率与远端转发

- 有预览连接时启用精确计时，并显式要求 Windows 11 尊重后台托盘进程的定时精度；无观看者时释放高精度计时请求。
- 摄像头暂未提供新帧时短暂重试，避免跳过整帧周期；显式关闭用完的帧与位图资源。
- 同一远端设备的多个观看窗口共享一条 HTTPS 上游连接，持续读取视频并只保留最新完整 JPEG，避免慢观看者积累旧帧。
- 禁用 MJPEG 响应的额外 HTTP 压缩，避免对已压缩的视频帧再次压缩。
- 预览 JPEG 质量从 75 调整为 60，保留最长边 1280 的预览尺寸；录像分辨率、码率和计划不变。
- 网页读取所选摄像头统计；本地显示实际预览出帧率，远端显示转发收到的帧率。原“延迟”指标改为实测帧间隔。

## 实机验证

2026-09-29，本机摄像头与 1080p 定时录像同时运行，浏览器请求头包含 `Accept-Encoding: gzip, br`：

| 测试 | 修复前 | 修复后 |
| --- | --- | --- |
| 本机预览 | 约 21.7 FPS；常见间隔 46 ms | 42 秒连续测试 29.22 FPS；P95 间隔 35 ms；最大 44 ms |
| AU 多窗口转发 | 多路测速约 5–7 FPS；P95 间隔约 459–487 ms | 两个转发窗口各 19.7 FPS；P95 间隔 70 ms；最大 125 ms |

修复后的两个 AU 转发窗口共享一条上游连接；AU 原有直接观看连接仍存在，因此测试时 AU 总连接数为 2，关闭两个转发窗口后恢复为 1。AU 本体仍为 4.8.1，远端源端的计时与 JPEG 修复需升级后才能生效。测试中的网络负载随观看连接数量变化，上述帧率是本次实机测量结果。

22 项 Rust 测试通过，包括完整 JPEG 长度解析、分片输入、异常长度、连接复用、丢弃旧帧和最后一个订阅者退出后的上游关闭。WiX 安装包校验通过。本机配置哈希未变，当前录像持续增长，替换前的录像已结束并成功解码。

构建产物在 `dist/release-v4.8.2`，包含客户端、SHA-256 校验文件及 x64 安装包。[正式版本 v4.8.2](https://github.com/syczk301/Monitor/releases/tag/v4.8.2) 供 4.8.x 客户端通过托盘“检查更新”升级；本机已替换为 4.8.2。

Windows 后台计时策略依据：[Microsoft SetProcessInformation 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation)。
