# 4.8.3：修复升级后的开机启动路径

如果曾更换安装目录，4.8.2 及此前版本会保留原启动项路径，托盘因此显示“开机启动：指向其他版本”。

- 客户端启动时把已有 CameraMonitor 启动项同步到当前运行程序，保留启动参数。
- 不创建已移除的启动项，不修改 Windows StartupApproved 禁用记录。
- 识别带参数和 Windows 扩展路径前缀的启动命令，避免误报其他版本。
- 当路径不一致时，托盘提供“修复开机启动路径”，修复后重新读取状态。
- `CameraMonitor.exe --repair-autostart` 可单独修复已有启动项，不启动摄像头。

AU 当前 4.8.2 可先在 AU 电脑运行 `scripts/Repair-Autostart.ps1`：脚本使用当前会话中唯一正在运行的客户端路径，写入并校验现有启动项，无需退出正在录像的程序。没有启动项或存在多个运行版本时不写入。

24 项 Rust 测试通过。隔离的注册表测试验证路径迁移、参数保留、重复执行、缺失启动项保持关闭，以及 Windows 禁用状态保持有效。PowerShell 5.1 语法检查与 WiX 安装包校验通过。测试不等同于 AU 重启登录验证。

[正式版本 v4.8.3](https://github.com/syczk301/Monitor/releases/tag/v4.8.3) 提供客户端、SHA-256 校验文件与 x64 安装包。4.8.x 客户端通过托盘“检查更新”升级，升级后会自动同步已有开机启动项。Windows 禁用的启动项仍需用户在系统设置中手动开启。
