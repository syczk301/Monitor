- Gradle 发布构建、Lint Vital 检查通过；使用官方 Maven 源下载到本机临时仓库的依赖完成构建。
- 6 项单元测试：Windows 发布文件过滤、正式手机版选择、禁止降级与下载地址限制；CONNECT 通道的 2 MB 二进制往返、连接失败处理、未认证访问拒绝。

## 联网验证限制

当前模拟器中 ZeroTier 停留在连接根服务器状态，GitHub 更新检查返回 `connection closed`，检查按钮恢复可点击；尚未获得实际更新的 APK，也未完成安装器更新流程验证。实际手机上的网络授权、监控画面、音频、录像访问和真实更新下载仍需联测，不能把 SDK 初始化通过当作这些链路已通过。

内置节点拥有自己的身份。手机安装后应在设置页保存网络与服务器地址，将该手机显示的节点 ID 在 ZeroTier 后台授权，授权后应用会继续连接并检查服务器健康状态。不要授权验证过程中模拟器生成的节点来替代真实手机。

GitHub 发布页面：https://github.com/syczk301/Monitor/releases/tag/v4.9.0 。发布资产为 `monitor-V4.9.0-release.apk` 和同名 `.sha256` 文件；更新器按 APK 文件版本识别手机版，不依赖最新 Windows 发布标签。此 Android 发布不替换 Windows 最新正式版 v4.8.4。

## 本机构建环境

当前 Java 在默认临时路径初始化 Unix-domain 回环失败；指定工作目录中的短临时路径可构建。构建脚本已包含该设置。本机 Java 访问 Maven 存在 TLS 握手故障，官方依赖副本保留在 `.test-runs/maven-mirror`；普通仓库配置的离线构建尚不能命中这些副本。其他联网正常的环境可使用正常仓库配置构建。

本次成功构建命令使用 `--init-script .test-runs/local-maven.init.gradle`，临时脚本仅将上述官方依赖副本放在 Google Maven 与 Maven Central 之前。
