# V4.9.1 验证记录

## 变更

V4.9.0 使用系统默认路由创建 libzt 原生 UDP socket，未避开其他 VPN。V4.9.1 新增 `PhysicalNetworkRoute`，请求 INTERNET + NOT_VPN 网络，在启动 libzt 前调用 Android `bindProcessToNetwork`，优先选择已验证的 Wi-Fi / 蜂窝网络。只修改监控 App 进程的网络绑定。

关闭内置连接会取消回调并清除本 App 的绑定。底层网络消失时保留旧绑定并显示等待状态，避免新 socket 意外回到 VPN。VPN 禁止绕过或没有可用底层网络时显示提示；无法保证系统强制 VPN 策略下自动绕过，用户可在 FlClash 中排除本 App。

由于 libzt 不公开其物理 UDP socket，采用进程级绑定。更新器单独使用系统默认网络的 SocketFactory 和 DNS，避免 GitHub 请求被切换为直连。关闭内置连接后恢复系统路由。

## 已通过

- 发布构建、Lint Vital、6 项单元测试。
- Android API 36.1 x86_64 模拟器：绑定网络具有 NOT_VPN，普通 UDP 能访问主机回显服务；关闭后恢复默认绑定。
- debug 测试 VPN 对本 App 建立默认路由并丢弃流量；绑定前 UDP 超时，绑定后回显通过，系统默认网络仍是 VPN。普通 TCP 可连接主机监听端口，更新器的系统网络 socket 则继续进入测试 VPN 并超时，证明其不受进程直连绑定影响。
- 原生 SDK 初始化、节点 ID 与关闭内置连接测试。
- 发布签名验证通过，签名与 V4.9.0 一致。

## 重现网络测试

仅在测试模拟器执行。先在主机开启 UDP 回显服务（18991）和 TCP 监听服务（18992）；再安装 debug APK 与 androidTest APK，给 debug 包授予测试 VPN app-op，执行 `PhysicalNetworkRouteTest`：

```powershell
adb -s emulator-5570 shell appops set com.monitor.intelligentflow ACTIVATE_VPN allow
adb -s emulator-5570 shell am instrument -w -e class com.monitor.intelligentflow.network.PhysicalNetworkRouteTest com.monitor.intelligentflow.test/androidx.test.runner.AndroidJUnitRunner
```

`BlackholeVpnService` 只位于 `src/debug`，使用允许绕过的测试 VPN，不包含在正式 APK；测试结束会停止服务。此测试验证 Android 路由机制，不能替代真实手机 FlClash 和实际 ZeroTier 节点连通性验证。
